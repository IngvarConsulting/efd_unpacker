# CLI EFD Unpacker

Один и тот же исполняемый файл открывает окно и работает из консоли. Три режима:

```text
efd_unpacker [--help|-h]
efd_unpacker <файл>
efd_unpacker info <файл>... [--json] [-tmplts <каталог>] [--dist <каталог>]
efd_unpacker unpack <файл>... -tmplts <каталог> [--dist <каталог>]
    [--only cf] [--dry-run] [--json] [--require-all] [--rar-tool <путь>]
```

На Windows вместо условного имени `efd_unpacker` обычно используется установленный `EFDUnpacker.exe`.

## 1. GUI-режим

Путь без команды открывает окно с уже добавленным файлом:

```bash
efd_unpacker /path/to/file.efd
```

## 2. Что принимается на вход

Обе консольные команды берут любое число файлов и разбирают их по содержимому, а не по расширению:

- `.efd` — шаблон конфигурации; один файл может нести несколько шаблонов;
- `.zip`, `.tar.bz2` — контейнеры со страницы релиза 1С, вложенные архивы читаются на месте;
- `.dmg` — только на macOS, образ монтируется на время осмотра;
- `.rar` — дистрибутивы платформы под Windows; читаются внешней программой, см. [раздел про .rar](#архивы-rar);
- `.run`, `.deb`, `.rpm`, `.pkg`, `.msi` внутри контейнеров — дистрибутивы платформы и наборы пакетов;
- `.cf`, `.dt`, `.epf` без `.efd` — файлы конфигураций.

Шаблоны ложатся в каталог шаблонов (`-tmplts`), дистрибутивы и наборы пакетов — в каталог дистрибутивов (`--dist`). Путь дистрибутива складывается из свойств самого файла: `platform/8.5.4.1683/windows-full-x86_64`.

## 3. `info` — осмотр без распаковки

```bash
efd_unpacker info ~/Downloads/*.efd ~/Downloads/*.zip
```

Печатает план: что найдено, какого объёма и куда легло бы при распаковке. На диск не пишет ничего — в том числе не регистрирует команду в `PATH`, как делает любой другой запуск собранного приложения.

```text
paths: /Users/me/.1cv8/1C/1cv8/tmplts

template  Бухгалтерия предприятия, редакция 3.0  3.0.180.28  2.1G  1c/Accounting/3_0_180_28
skipped   Test                                               135K  already installed
error     missing.efd                                              File not found

3 files · 1 template · 1 skipped · 1 error · to write: 2.1G · 0.4s
```

Первая колонка — вид элемента (`template`, `distribution`, `packages`, `content`, `other`) либо исход, если он важнее вида: `skipped` с причиной в последней колонке, `error` с сообщением. Общее начало путей выносится в строку `paths:`; путь шаблона внутри каталога — тот, что записан в самом `.efd`.

Каталоги `-tmplts` и `--dist` здесь необязательны и нужны только для того, чтобы план показал настоящие пути назначения и настоящие «уже установлено». Без них берётся каталог шаблонов по умолчанию и каталог `dist` рядом с ним.

## 4. `unpack` — распаковка

```bash
efd_unpacker unpack ~/Downloads/*.efd -tmplts ~/.1cv8/1C/1cv8/tmplts
```

Печатает тот же план, но первая колонка показывает, что вышло на самом деле: `written`, `skipped`, `error`. Отказ на одном файле не останавливает остальные.

```text
written  Бухгалтерия предприятия, редакция 3.0  3.0.180.28  2.1G  1c/Accounting/3_0_180_28
skipped  Test                                               135K  already installed

2 files · 1 template · 1 skipped · written: 2.1G · 14.8s
```

Флаги:

| Флаг | Что делает |
|------|------------|
| `-tmplts <каталог>` | Каталог шаблонов. Обязателен. Синоним — `--output`. Создаётся, если его нет. |
| `--dist <каталог>` | Каталог дистрибутивов. По умолчанию `dist` рядом с каталогом шаблонов: для `~/.1cv8/1C/1cv8/tmplts` это `~/.1cv8/1C/1cv8/dist`. Синоним — `-dist`. |
| `--only cf` | Не писать выгрузки `.dt` — демонстрационные базы, которые весят примерно столько же, сколько сама конфигурация. Единственное поддержанное значение — `cf`. Шаблон, из которого фильтр унёс всё содержимое, не записывается вовсе. |
| `--dry-run` | Показать план и остановиться, не записав ни байта. То же, что `info`, но с обязательным `-tmplts`. |
| `--json` | Машинный вывод вместо таблицы, см. ниже. |
| `--require-all` | Считать пропуск отказом: код возврата `1`, если что-то пропущено. |
| `--rar-tool <путь>` | Программа для `.rar`, которую проверить первой. Поиск по системе не отменяет. |

Пути принимаются абсолютные, относительные и с `~`.

«Уже установлено» определяется по наличию каталога назначения. Каталог, оставшийся от прерванной распаковки, тоже считается установленным: в консоли его нужно удалить руками, в окне — настоять на распаковке щелчком по знаку строки.

## 5. Коды возврата

| Код | Значение |
|-----|----------|
| `0` | Успех. Пропуски — «уже установлено», «нет программы для .rar» — успехом остаются: это нормальные исходы, а не проблемы. |
| `1` | Содержательный отказ хотя бы на одном файле: файл не найден, архив повреждён, нет прав, попытка записи за пределы каталога. С `--require-all` — также любой пропуск. |
| `2` | Ошибка ввода: неверный синтаксис. Печатается текст помощи. |

Ошибкой ввода считается всё, что не укладывается в грамматику «сначала файлы, потом только флаги»:

```bash
$ efd_unpacker unpack file.efd --tmplts out    # два дефиса вместо одного
$ efd_unpacker unpack file.efd -tmplts out EXTRA    # голый аргумент после флагов
$ efd_unpacker unpack file.efd -tmplts    # флаг без значения
$ efd_unpacker unpack file.efd -tmplts out --only dt    # неподдержанное значение
$ efd_unpacker unpack file.efd    # нет -tmplts
$ efd_unpacker UNPACK file.efd -tmplts out    # другой регистр команды
$ echo $?
2
```

Сокращения флагов не принимаются: `-t` и `-tmp` — ошибка ввода, а не `-tmplts`. Значение, начинающееся с дефиса, значением не считается.

Команды `unpack` и `info` всегда обрабатываются в консоли и никогда не открывают окно. Чтобы открыть файл в окне, передайте путь без команды.

## 6. `--json`

Один документ на stdout, ключи — константы, а не переводы:

```json
{
  "schema": 2,
  "items": [
    {
      "kind": "supply",
      "action": "write",
      "name": "Test",
      "version": "",
      "source": ["1cv8.efd"],
      "files": 4,
      "bytes": 138462,
      "destination": "/Users/me/.1cv8/1C/1cv8/tmplts/IngvarConsulting/Test"
    }
  ],
  "totals": {
    "files": 1, "items": 1, "write": 1, "skip": 0, "fail": 0,
    "bytes": 138462, "seconds": 0.0
  }
}
```

- `kind` — `supply`, `platform`, `packages`, `content`, `other`.
- `action` — что планировалось: `write`, `skip`, `fail`. У пропуска есть `reason`, у отказа — `error` с кодом и деталями.
- `outcome` появляется после `unpack`: `written` или `failed`. Отдельный ключ, а не подмена `action`: потребителю нужно и то, что планировалось, и то, что вышло.
- `totals` после `unpack` дополняется полями `written`, `failed`, `skipped`, `bytes_written`, `cancelled`.
- `schema` растёт, когда меняется смысл существующих ключей, а не когда добавляется новый: потребитель обязан пережить незнакомое поле.

Ход работы печатается в stderr и только в терминале, поэтому `info --json | jq` разбирает чистый документ, а в логе CI бегущей строки нет.

## 7. Язык вывода

Таблица и сообщения об ошибках идут на языке системы — русском на русской локали, английском на любой другой. `--json` от локали не зависит.

## Архивы `.rar`

Чистый Python RAR5 не читает. Распаковку делает внешняя программа, которую приложение ищет в системе и проверяет на самом архиве: сначала чтение оглавления, затем пробное извлечение самой маленькой записи. Поддержаны три семейства:

| Семейство | Программы | Где обычно есть |
|-----------|-----------|-----------------|
| libarchive | `bsdtar`, на Windows системный `tar` | macOS и Windows 10+ из коробки, Linux — пакет `libarchive-tools` |
| 7-Zip | `7zz`, `7z`, `7za` | ставится отдельно; на Windows — `7-Zip` |
| The Unarchiver | `lsar` + `unar` | macOS и Linux; на Windows не ищется |

Если ни одна не найдена или ни одна не справилась с этим архивом, файл пропускается с причиной «нет программы для .rar». Какая программа нашлась и чем читался последний архив, видно на экране «Инструменты для .rar» в окне.

## Помощь

```bash
efd_unpacker --help
efd_unpacker -h
efd_unpacker unpack --help
efd_unpacker info --help
```

`--help` и `-h` распознаются в любой позиции аргументов и печатают один и тот же текст с кодом возврата `0`. Первые строки — название и версия сборки.

## PATH

| Платформа | Вариант поставки | PATH |
|-----------|------------------|------|
| macOS | `DMG` | автоматически после первого запуска установленного `.app` |
| Windows | `setup.exe` | автоматически через установщик |
| Linux | `DEB` | автоматически |
| Linux | `AppImage` | автоматически после первого запуска |

### macOS

После первого запуска уже установленного `EFDUnpacker.app` приложение создаёт пользовательский launcher `efd_unpacker` в управляемом каталоге и добавляет его в `PATH` только пока существуют и launcher, и само приложение.

Важно:
- если приложение запущено прямо с примонтированного `.dmg`, PATH не настраивается;
- после установки в `Applications` просто запустите приложение ещё раз;
- после удаления приложения новая shell-сессия больше не будет добавлять `efd_unpacker` в `PATH`;
- если старая shell-сессия ещё помнит команду, launcher при первом вызове сам удалится;
- блок дописывается и в login-профиль, и в rc-файл шелла (`~/.zshrc`, `~/.bashrc`), поэтому команда доступна и в обычном окне терминала;
- для уже открытого терминала откройте новую вкладку;
- перед первой правкой рядом с профилем создаётся одноразовая копия `*.efd-unpacker.bak`;
- запуск с командой `info` ничего из этого не делает: команда обещает не писать на диск.

### Linux AppImage

После первого запуска `AppImage` приложение создаёт пользовательский launcher `efd_unpacker` в управляемом каталоге и добавляет его в `PATH` только пока существуют и launcher, и сам `AppImage`.

Если файл `AppImage` был перемещён, просто запустите его ещё раз, чтобы launcher обновился. Если `AppImage` удалён, новая shell-сессия больше не будет добавлять `efd_unpacker` в `PATH`.

### Windows setup.exe

Windows setup добавляет приложение в системный `PATH`, поэтому после установки бинарь можно вызывать из консоли без перехода в каталог установки.

`EFDUnpacker.exe` — один бинарь и для GUI, и для CLI. Окно консоли появляется только тогда, когда команду запустили из уже открытой консоли: в этом случае `--help`, таблица плана и `--json` печатаются как на Linux и macOS. При двойном клике по `.efd`, запуске ярлыка из меню Пуск или с рабочего стола консоль не показывается — открывается сразу GUI.

## Совместимость

CLI использует единый прикладной слой и работает одинаково по смыслу на Windows, Linux и macOS.
